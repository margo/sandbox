# Margo Conformance Test Suite - Vendor Customization Guide

## Overview

This conformance test suite allows Margo vendors and spec creators to test their implementations against the Margo specification using real collection.json files and test scenarios.

**Important:** Example/placeholder values are provided throughout this tool. You **MUST** customize these values with your actual device configuration before running tests.

---

## Example Values to Customize

### 1. Device Environment Configuration

**File:** `conformance/wfm-supplier/newman-data/device-agent.env.json`

All values marked with `EXAMPLE:` below must be replaced with your actual device identifiers:

| Key | Current Example | Required Change | Purpose |
|-----|-----------------|-----------------|---------|
| `deviceId` | `device-1779864226` | Your device identifier | Unique identifier for your test device |
| `clientId` | `client-cb336dc9443afc98-1779469290` | Your client identifier | Unique identifier for your device client |
| `deploymentId` | `demo-deployment-001` | Your deployment identifier | Identifier for deployment being tested |
| `vendor` | `Margo Vendor` | Your company/vendor name | Appears in device capabilities manifest |
| `modelNumber` | `MARGO-MODEL-01` | Your actual device model | Appears in device capabilities manifest |
| `serialNumber` | `SN-device-1779864226` | Your device serial number | Appears in device capabilities manifest |

### 2. Where These Values Appear

These example values appear in multiple places:

1. **Direct environment variables:** Lines like `"value": "device-1779864226"`
2. **Embedded in JSON payloads:** Inside `capabilitiesRequest` and `capabilitiesUpdateRequest` payloads
3. **Request bodies:** Used by Newman to populate POST/PUT request bodies

## Customization Steps

### Step 1: Edit Environment File

```bash
# Open the environment configuration
nano conformance/wfm-supplier/newman-data/device-agent.env.json
```

Replace all example values:
- Search for: `device-1779864226` → Replace with your device ID
- Search for: `client-cb336dc9443afc98-1779469290` → Replace with your client ID
- Search for: `Margo Vendor` → Replace with your vendor name
- Search for: `MARGO-MODEL-01` → Replace with your model number
- Search for: `SN-device-1779864226` → Replace with your serial number
- Search for: `demo-deployment-001` → Replace with your deployment ID

### Step 2: Verify Your Postman Collection

If using custom Postman collection (instead of groups):
```bash
# Edit or upload your collection
conformance/Data-Generator/wfm-supplier/postman_collection.json
```

The collection can contain:
- Your actual API endpoints
- Your actual request definitions
- Lorem Ipsum placeholders will be replaced at runtime with environment values

### Step 3: Run Tests with Your Configuration

```bash
# Run the conformance test runner
cd conformance-persona-test/conformance
./run-tests.sh

# Select: 
# - Persona: 1 (WFM Supplier)
# - Group: Or enter your custom setup
# - WFM URL: Your test WFM server endpoint
```

## Important Notes

### About Lorem Ipsum in Collections

**Q: Why are there Lorem Ipsum placeholders in the Postman collection?**

**A:** These are automatically generated by Portman during OpenAPI → Postman conversion. This is expected and handled by the test runner:

1. The conformance tool detects Lorem Ipsum placeholders
2. At runtime, these are **automatically replaced** with actual values from your environment file
3. Your WFM server receives **real device data**, not Lorem Ipsum

### Collection Patching

The tool automatically patches collections to:
- Replace hardcoded Lorem Ipsum with environment variable references
- Convert `:parameter` syntax to `{{parameter}}` for Newman substitution
- Map API endpoints to appropriate request payloads

You can disable patching for well-formed custom collections:
```bash
PATCH_COLLECTION=false ./conformance/run-tests.sh
```

## Group-Based Testing

If using pre-defined test groups, no customization is needed:

```bash
./run-tests.sh
# Select: Persona → Group → WFM URL
# Tool uses: Data-Generator/wfm-supplier/groups/{groupname}/
```

Each group folder contains:
- `group.json` - Metadata and test case IDs
- `postman_collection.json` - Pre-filtered collection (8 test items)
- `test-scenarios.json` - Test definitions

## Troubleshooting

### Issue: Tests fail with "device not found"
**Solution:** Verify your `deviceId` and `clientId` in environment file match your WFM registration

### Issue: Tests fail with payload validation errors  
**Solution:** Check that vendor, modelNumber, serialNumber match your actual device specs

### Issue: Collection patching failing
**Solution:** Ensure your collection is valid JSON and follows Postman format

### Issue: Need to see what values are being used
**Solution:** Open the HTML report after tests complete:
```bash
# Reports are saved in:
conformance/Runner/wfm-supplier/wfm-test-report-*.html
```

## RFC 9421 HTTP Message Signing (conformance-2)

The `conformance-2` folder includes RFC 9421 HTTP message signing support:

- Requests are routed through a signing proxy
- Signatures are added before reaching WFM
- Useful for testing signature verification implementations
- Same customization steps apply
